# Турбопульт

CRM-инбокс для поддержки: клиент пишет в мессенджер → обращение попадает в CRM →
оператор отвечает в CRM → ответ уходит клиенту обратно в его мессенджер.

Каналы: Telegram и MAX одновременно, в одном списке.

**Демо интерфейса:** https://sin-sluhi.github.io/turbopult/ — работает без
сервера, на вымышленных обращениях. Собирается командой
`python web/_build.py web` в `docs/index.html`.

## Устройство

```
web/index.html        интерфейс оператора (демо работает без бэкенда)
backend/app/
  adapters/base.py    интерфейс мессенджера — единственное, что знает ядро
  adapters/telegram.py
  adapters/maxru.py   platform-api2.max.ru
  core.py             приём входящих, отправка ответов, статусы
  db.py, schema.sql   SQLite
  events.py           SSE — новые сообщения сами приходят во вкладку
  main.py             вебхуки и API
dev_inject.py         вбросить входящее без реального бота
```

Ядро оперирует только `provider` как строкой. Новый канал = ещё один файл в `adapters/`.

## Запуск

```
cd backend
python -m venv .venv && .venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env      # вписать токены
uvicorn app.main:app --reload --port 8000
```

Интерфейс — http://localhost:8000, документация API — /api/docs.

Проверить логику без токенов и домена:

```
python dev_inject.py telegram "Здравствуйте, не видит ключ"
```

## Боевая настройка

Оба мессенджера требуют публичный HTTPS с сертификатом доверенного УЦ;
самоподписанные не принимаются. MAX дополнительно принимает только порт 443.

```
POST /api/setup/telegram
POST /api/setup/max
```

Проверить, что токен живой: `GET /api/setup/max` → вернёт профиль бота.

## Что важно помнить про MAX

- токен в заголовке `Authorization`, не в query;
- получатель — query-параметр `chat_id` или `user_id`;
- секрет вебхука приходит в `X-Max-Bot-Api-Secret`;
- не больше 2 сообщений в секунду в один диалог, 30 rps на API в целом;
- при сбое доставки events повторяются до 10 раз, поэтому в базе есть
  таблица `seen_updates` — без неё один вопрос клиента задвоится;
- если 8 часов подряд вебхук не отвечает 200, MAX сам отписывает бота.

Бот в MAX создаётся только с верифицированным профилем юрлица, ИП или
самозанятого и проходит модерацию. Telegram-бот делается за минуту — поэтому
разработку ведём на нём, а MAX подключаем тем же кодом, когда будет токен.

## Кружок присутствия клиента

Правило:

| Кружок | Условие |
|---|---|
| зелёный | клиент в чате, с момента входа меньше 5 минут |
| оранжевый | прошло больше 5 минут, но видно, что клиент печатает |
| красный | больше 5 минут тишины либо вышел более 5 минут назад |

Логика в `app/presence.py`, она работает от абстрактных сигналов.

**Ограничение, которое надо знать заранее.** Bot API ни Telegram, ни MAX не
присылают событие «пользователь печатает» и не сообщают, открыт ли у клиента
чат. Отследить по-честному можно только:

- вход — `bot_started` в MAX, разблокировка бота в Telegram;
- выход — `bot_stopped` и `dialog_removed` в MAX, блокировка в Telegram;
- активность — само входящее сообщение.

Поэтому зелёный и красный работают на реальных данных, а оранжевый требует
источника события «печатает»: мини-приложение MAX или веб-виджет на сайте,
где присутствие видно напрямую. Функция `presence.mark_typing()` уже ждёт
этот сигнал — подключить останется одной строкой.

## Архив по папкам

Список папок — `app/folders.py`, он же отдаётся в интерфейс через
`GET /api/folders` со счётчиками. Убрать обращение в архив:

```
POST /api/conversations/{id}/archive   {"folder": "tsn"}
```

Если тема не ложится ни в одну структуру — `{"folder": "undef"}`,
папка «Не определённая тема». В переписку при этом пишется системная строка,
так что видно, кто и куда убрал вопрос.

## Анкета перед вопросом

Бот задаёт четыре вопроса, прежде чем пустить клиента к специалисту:
номер ключа или лицензии, организация, имя и фамилия, мобильный телефон.
Сценарий и проверки — в `app/intake.py`.

Пока анкета не заполнена, обращение **не создаётся**: оператор не увидит
диалог без контекста. Состояние живёт в `contacts.intake_step`, отдельной
таблицы не нужно — шагов четыре и они строго последовательные.

Каждый ответ проверяется, при ошибке бот переспрашивает и не идёт дальше:

- ключ приводится к виду `ТС-14782` из `тс14782`, `TC 14782` и подобного;
  «нет ключа» — допустимый ответ для тех, кто ещё не купил;
- имя и фамилия — минимум два слова без цифр и символов;
- телефон нормализуется к `+7 916 204-77-10` из любых 10–11 цифр.

Клиент может прервать анкету словом «отмена» и начать заново позже.

Прогнать анкету без бота и домена:

```
cd backend
python dev_inject.py "ТС-14782"
python dev_inject.py "ООО Проектстрой"
python dev_inject.py "Ирина Кузнецова"
python dev_inject.py "89162047710"
python dev_inject.py "Не видит ключ после переустановки Windows"
```

Ответы бота печатаются в консоль. Обращение появится только после
пятого сообщения — первые четыре съест анкета.

## Умный поиск по архиву

```
GET /api/archive/search?q=не+видит+ключ
```

Ищет по всем папкам сразу и возвращает обращения с оценкой совпадения,
найденными словами и фрагментом переписки. Логика — в `app/search.py`:

- сравниваются не слова, а основы, поэтому «ключа», «ключом» и «ключи»
  находят одно и то же;
- работает словарь синонимов предметной области: по запросу «ключ»
  находятся обращения про HASP, лицензию и активацию, по «арпс» — про XML
  и выгрузку;
- вес зависит от места совпадения: тема и теги важнее тела переписки;
- если нашлись все слова запроса, оценка удваивается.

Для нескольких тысяч обращений этого достаточно. Когда архив вырастет,
то же самое переносится на FTS5 без изменения интерфейса функции.

## Запуск

`backend\start.cmd` — двойной клик. Первый раз сам создаст окружение и
поставит зависимости, дальше просто поднимает сервер.

Пульт открывается на http://localhost:8000, вход по паролю из `.env`
(`ACCESS_PASSWORD`). Пока окно открыто — сервис работает.

## Как дать доступ сотруднику

Сервер слушает всю сеть (`0.0.0.0:8000`), но снаружи его закрывают два
шлагбаума, которые к коду отношения не имеют.

**Способ 1 — туннель (быстро, с шифрованием).** `backend\tunnel.cmd`
спросит подтверждение, поставит cloudflared и выдаст ссылку вида
`https://...trycloudflare.com`. Ни брандмауэр, ни роутер не участвуют,
серый IP провайдера не мешает. Закрыли окно — доступ закрылся.

**Способ 2 — свой порт наружу.** От администратора:

```
netsh advfirewall firewall add rule name="Turbopult 8000" dir=in action=allow protocol=TCP localport=8000
```

и проброс порта 8000 на локальный адрес компьютера в настройках роутера.
Адрес получится вида `http://<внешний IP>:8000`, без шифрования.
Не сработает, если провайдер выдаёт серый IP за своим NAT — проверьте
WAN-адрес в статусе роутера.

**Способ 3 — VPS.** Правильный вариант для постоянной работы: домен,
сертификат, вебхук вместо опроса, машина не выключается вместе с ноутбуком.

## Кто может войти

`ALLOW_IPS` в `.env`:

- пусто — только этот компьютер;
- `127.0.0.1,192.168.0.0/24,203.0.113.7` — перечисленные адреса и подсети;
- `*` — любой адрес, единственная защита остаётся паролем.

При отказе страница называет адрес, который увидел сервер, — его и надо
добавить в список. Отказы пишутся в лог.
