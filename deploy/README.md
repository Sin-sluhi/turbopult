# Развёртывание на сервер

Домашний компьютер не годится для постоянной работы: он выключается,
внешний IP меняется, а туннель через Cloudflare на этой сети не проходит —
провайдер рвёт TLS-рукопожатие. Сервер решает всё это разом.

## Что нужно

1. **VPS** — любой российский хостинг (Selectel, Timeweb, Reg.ru).
   Минимальный тариф хватит с запасом: 1 ядро, 1 ГБ памяти, ~250 ₽ в месяц.
   Образ — Ubuntu 22.04 или 24.04.
2. **Домен** — можно самый дешёвый в зоне .ru. В его настройках создать
   A-запись, указывающую на IP сервера.

## Развёртывание

Скопировать папку проекта на сервер и выполнить:

```
sudo bash deploy/setup.sh pult.ваш-домен.ru почта@ваша.ру
```

Скрипт сам поставит Python и nginx, создаст службу с автозапуском,
настроит обратный прокси и получит сертификат Let's Encrypt.

Через несколько минут пульт открывается по `https://pult.ваш-домен.ru`
и работает круглосуточно. Сотрудникам даёте эту ссылку и пароль.

## После развёртывания

В `/opt/turbopult/backend/.env`:

```
PUBLIC_URL=https://pult.ваш-домен.ru
TELEGRAM_MODE=webhook
TRUST_PROXY=1
```

Перезапустить и перевести бота на вебхук:

```
systemctl restart turbopult
curl -X POST https://pult.ваш-домен.ru/api/setup/telegram
```

Вебхук лучше опроса: Telegram сам присылает события, задержка меньше,
нагрузки нет. Для MAX вебхук вообще единственный рабочий режим.

## Управление

```
systemctl status turbopult      состояние
systemctl restart turbopult     перезапуск
journalctl -u turbopult -f      живой лог
```

## Обновление

Скопировать изменившиеся файлы в `/opt/turbopult` и перезапустить службу.
База `backend/crm.db` и вложения `backend/media` переживают обновление —
не перезаписывайте их.
